# 轻量资金 v0.9 施工规范

状态：F0–F4 已实现，F5 完整验收进行中。用户于 2026-09-06 授权 v0.9 与 v0.10 分步实施。基线为已发布 sales-v0.8 / 5a5c0e0，迁移 0011_sales_returns。以下细则属于原规范未细化部分的本阶段实现选择，原业务硬约束继续有效。

## 1. 目标与边界

完成应收、收款、应付、付款、部分核销、退货冲减及退款、错误收付款冲销、期初往来和来源追溯。仅记录企业实际发生的收付款，不执行银行转账。单币种 CNY，沿用服务端 Decimal、NUMERIC(20,4) 金额；不擅自把四位商业金额舍入成两位，也不自动抹去尾差。

不做总账、会计凭证、税务、发票、汇兑、银行对接、票据、复杂审批、跨客户/供应商净额抵销或预收预付管理。客户信用及退款余额仅用于已发生退货或明确期初余额，不提供无来源超额收付。

## 2. 事实与切换原则

- 订单确认、关闭与结算状态独立；资金不能改变库存及履约数量。
- 新应收来自实际过账销售出库的冻结销售金额；新应付来自实际过账采购入库的冻结商业金额。成本、毛利及采购退货库存价值均不能充当收付款金额。
- 退货减少原来源的债权债务。已结算部分形成可退款余额，实际退款另留收付款事实。退货不等于钱已经退回。
- 金额汇总以有效来源和收付款事实为准，可对账；过账事实禁止删除或重写。纠正追加反向事实。
- 租户必须有明确的资金启用切点。升级不自动认定所有旧单据尚未结算；历史欠款经期初录入，记录对象、方向、金额与说明。
- 资金启用与原业务过账通过组织级事务锁排序划定切点，不依赖客户端日期或事务开始时刻；避免启用和过账并发造成漏记。
- 历史采用来源化期初：显式绑定同对象的历史有效出库/收货，确认切点时该来源的未结余额（零为已结清，负数为已有退货形成的待退款），冻结当时有效商业净额。历史已结清差额不是本系统新收到或付出的现金。
- 启用后补绑定从同对象、同余额方向的期初额度转移，不能在期初总额之外再增加欠款；正余额使用尚未核销额度，负余额使用尚未退款额度并再次明确确认。历史零余额绑定也必须显式操作。绑定金额范围为负的历史已退商业金额至有效商业净额，后续退货减少该来源欠款，超出未结部分形成待退款。
- 启用前原单没有期初映射时，后续退货/冲销以 `LEGACY_FUNDS_MAPPING_REQUIRED` 拒绝，并提供先完成来源绑定的处理路径；不会部分提交库存或静默漏记资金。

## 3. 收付款与核销

同一张收付款单只属于一个往来对象及应收/应付方向，可以核销该对象多笔来源，支持部分结算。服务端校验各来源、剩余额度、金额合计和当前权限；不允许跨租户、跨对象核销，重复来源行必须拒绝。

部署业务时区由 `BUSINESS_TIMEZONE` 明确配置，默认 `Asia/Shanghai`，启动校验 IANA 时区。商业来源日期按过账时刻转换到该业务时区；资金营业日期由录入明确选择，不能早于启用业务日期。后续经营统计沿用同一时区。

收付记录保留业务日期、方式、外部参考号、说明、来源分配与操作人。金额由服务端验证，收款/付款/客户退款/供应商退款方向明确。列表和详情必须展示尚未核销或尚待退款的来源，用户不需要在浏览器手算。

冲销必须校验后续依赖及额度，保留原单和反向记录，不能把原单回到草稿。原销售/采购冲销仍保留严格末笔库存限制；资金接入只能增加明确的结算依赖校验，不能绕过库存引擎。

所有资金变更按组织、AR/AP、往来对象串行锁定。业务过账在幂等闭包入口先取得切点共享锁，然后沿用既有订单/来源/库存锁序进入资金对象锁；历史绑定先切点、再原单共享锁、最后资金对象锁。纯现金命令不反向取得订单/库存锁。有效核销/退款依赖存在时拒绝原来源冲销，先完成对应资金纠正；精确依赖规则及期初转移事实见 [ADR0015](adr/0015-lightweight-funds.md)。

## 4. 安全、事务与界面

沿用 RuntimeContext、HttpOnly 会话、同源 /api、非特权 forge_app、FORCE RLS、复合租户外键、Problem Details/request ID、Audit/Outbox/幂等。应用 Commands 包含确定性校验；FastAPI 只处理契约与依赖。核心收付款与资金来源接入在数据库事务内完成，不交由 Celery 异步决定成败。

资金读取、收付款、退款、冲销和期初/启用分别授权。仓管可以依现有权限过账业务，但不能因此读取资金明细；服务端内部从冻结来源接入资金。权限校验在幂等回执读取之前。

工作台 /funds，旧 /finance 入口兼容。分页、来源跳转、往来筛选、服务端汇总、核销选择、冲销原因和不确定提交重试均需支持。OpenAPI 生成前端类型，金额只展示服务端字符串。重复点击、网络响应丢失、切换单据和浏览器导航不能造成重复收付款。
