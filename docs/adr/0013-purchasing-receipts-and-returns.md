# ADR 0013：采购订单、收货与退货

Status: Accepted for implementation — 2026-09-05。用户授权“规范明确后直接分步实现采购功能”；以下为本阶段明确的实施选择，沿用权威上下文，不另行设计 ERP。

依据：迁移上下文4.4、5、7、9、11–16；库存ADR0012。原规范没有完整定义超收、退货计价、分批履约及应付边界，以下逐项固定，交付时保留限制说明。

| 决策 | 本阶段实施 | 理由与边界 |
|---|---|---|
| P1 订单与履约 | 单供应商/单收货仓、每商品一行；确认不改库存；允许分批，禁止超收；确认后商业内容冻结；显式关闭剩余，不自动关闭 | 订单状态DRAFT/CONFIRMED/CLOSED/CANCELLED与收货状态UNRECEIVED/PARTIAL/RECEIVED分开；不增加订单修订版本工作流 |
| P2 金额与历史单位 | 采购单价为所选采购单位价，金额=数量×单位价，20,4金额/20,6数量单价；确认订单冻结单位因子；收货沿用该快照 | 向InventoryEngine传准确入库金额，不能先把箱价舍入成个价再乘回。收货价格可显式填写，不填则沿用订单价 |
| P3 来源集成 | 库存单据新增PURCHASE_RECEIPT/PURCHASE_RETURN，采购附属表以租户复合外键关联订单/收货行；保持现有流水来源外键 | 不把采购伪装成手工调整，不改旧流水、不改成没有外键的字符串来源；采购Command拥有生命周期，普通库存Command拒绝这些类型 |
| P4 退货 | 必须引用未冲销的原收货，原供应商、原仓、原单位；累计有效退货不超过原实收；退货不自动重开订单待收量 | 补货另开订单。退货库存按当前移动平均成本出库；参考退货金额按原收货价，两者分别保存，差额不是损益凭证或退款 |
| P5 冲销与末笔限制 | 沿用各受影响库存键严格末笔整单冲销；收货冲销恢复订单实收投影，退货冲销恢复可退额度；依赖存在则拒绝 | 不支持部分冲销、历史成本重算/级联。退货不是冲销；已关闭订单不会因冲销自动重开 |
| P6 资金与规模 | v0.7不生成Payable/Payment，不显示虚假已付款/未付款状态；结算能力以后独立接入。200行/单，100条/页 | 原文“可生成Payable”为可选；订单/收货/退货参考金额不是应付或收付款事实。继续同事务Audit/Outbox/幂等、RLS和同源API |

退货尾差：对原收货行最后一次退完，参考金额取原收货金额减已生效退货金额，确保精确归零；部分退货若舍入超出剩余金额则明确拒绝，不能静默截断。数量/价格不接收float或不可表示的小数。新收货要求相关主数据仍有效，历史冲销按原快照可执行。

需要后续评审的扩展：多仓收货、超收容差、确认单修订、退货原成本追踪、运费分摊、税额/折扣、多币种与资金核销。上述均不在本阶段默认加入。
