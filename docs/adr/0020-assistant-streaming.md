# ADR 0020: Public assistant activity and streamed replies

Status: Implemented under the user's 2026-09-06 request; integrated acceptance pending.

The assistant currently returns a turn only after the graph finishes. Add optional SSE content negotiation to the existing idempotent message, brief and retry endpoints. The ordinary JSON contract stays available. Events carry validated turn snapshots, public text deltas and a final committed receipt. They contain no model reasoning, credentials, raw tool arguments or checkpoint state. A final event is authoritative; a dropped connection retains the original submission key and requires receipt recovery.

`Accept: text/event-stream` selects SSE on the existing POST message, brief and turn-retry endpoints. Each frame has one JSON `data` field: `snapshot`/`complete` carry `turn: TurnRead`, `delta` carries `turn_id` and public `delta`, and `error` carries `status`, `code`, `detail`, `request_id`. Only unused envelope members are omitted; nested DTO nulls match the JSON API. `complete` ends this request but can carry an already-leased `RUNNING` receipt on exact-key replay; clients must retain uncertainty until a terminal turn is confirmed. Application activity has stable IDs, model/query/draft/reply kinds, running/complete/failed states and actual server timestamps. The turn also exposes business/casual interaction and whether a gentle ERP suggestion was appended. The OpenAPI contract describes JSON and SSE separately.

SSE responses send `Cache-Control: no-store, no-transform` and `X-Accel-Buffering: no`. In particular, `no-transform` prevents the same-origin Next rewrite from compressing and buffering the stream; global HTTP compression remains enabled.

Persist bounded application activity in the existing private `assistant_turns.response` JSON alongside evidence. Every progress write uses the current authenticated context, owner RLS, attempt fence and lease. No schema migration or new infrastructure is required. Tool completion is emitted only after the authorized Query has completed and its DTO has been validated. Restored history shows actual recorded activity. Transport cancellation cancels the graph; the existing lease and checkpoint recovery handle interrupted attempts.

Each outgoing frame rechecks the session, organization, owner, conversation permissions/provider version and current attempt; public deltas also require a live attempt lease. No database transaction spans model waits or SSE queue waits. Retry closes the previous interrupted activity with a server timestamp and reuses the original turn and idempotency key. Public activity and evidence share existing private response bounds, retention erasure and FORCE RLS.

The HTTP response explicitly closes its event generator in `finally`, covering both ASGI 2.3 disconnect cancellation and ASGI 2.4 send-side `OSError`. The response-level tests exercise both branches and assert the running graph is canceled before response teardown finishes; relying only on clients or eventual generator garbage collection would leave execution running after a disconnected socket.

Model routing remains validated structured decisions. A new `chat` decision can request a short casual reply in a separate, bounded OpenAI-compatible streaming call without business facts or tools. Business replies remain server-authored and never stream unvalidated model-generated financial values. Count consecutive completed casual turns from server history; beginning with the third, append a gentle ERP suggestion. A business turn resets this count. Neither the browser nor model supplies the count. Stream only public response text, ignore upstream reasoning fields, enforce framing/size/deadline limits, and fail clearly when the configured service cannot stream.

Ordinary daily conversation, general knowledge and personal numbers remain allowed. A narrow application guard redirects explicit enterprise data/action requests that the model incorrectly labels as chat and refuses explicit instruction/credential extraction. A query cannot later switch to chat. Before releasing actual upstream text, accumulate through sentence boundaries and reject unsupported enterprise numeric assertions, claimed business execution or hidden-reasoning tags. This bounded output guard supplements the structured decision policy; it is not a general semantic verifier. Failed business queries also break the casual streak; failed casual replies neither count toward it nor manufacture a completed reply. Business evidence arrives as whole validated Query snapshots, never as simulated tokens.

Use official beUI Chat App message proportions, solid user bubbles, open assistant content, AgentActivity disclosures and PromptInput. Place compact business result cards in the thread and retain mounted detailed evidence/draft editors. Preserve keyboard access, reduced motion, identity isolation and uncertain submission locks.

Acceptance: real incremental delivery before completion; exact-key replay; disconnect and provider-failure recovery; session/permission/owner isolation during streaming; casual threshold/reset and prompt-injection evals; typed cards and source links; browser stream behavior; full checks and exact-commit CI.

Controlled backend evidence includes 11 versioned chat eval cases in `apps/api/evals/assistant-chat.json`, protocol and boundary tests in `test_assistant_streaming.py`, and upstream framing/error tests in `test_assistant_provider.py`. These prove guards and recovery only. The configured provider's actual streaming support and conversational routing require separate live acceptance; browser composition, full regression and final commit CI are recorded by the integration task.
