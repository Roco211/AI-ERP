# 资料导入使用与恢复说明

每次选择一种资料类型，下载当前模板，填写后上传。模板第一行含中文列名和字段批注；不要修改列名，不要在数据区放说明行。只接受 `.xlsx`，最多10,000,000字节、10,000条非空数据行、64列。多工作表文件必须填写要导入的工作表名称；其他工作表仍会接受安全检查。

## 资料类型及定位方式

| 类型 | 定位键 | 引用与注意事项 |
|---|---|---|
| 分类 | 编码 | 父分类须已存在；属性模板使用现有分类编辑支持的JSON数组 |
| 品牌 | 编码 | 编码区分大小写 |
| 单位 | 编码 | 不自动推断单位或换算关系 |
| 客户 | 编码 | 价格等级为standard、retail或wholesale；新增留空默认standard |
| 供应商 | 编码 | 电话、联系信息按文本填写 |
| 仓库 | 编码 | 不导入库存数量 |
| 商品 | 商品编码 | 分类和基础单位必填；引用品牌、供应商和默认单位须已存在 |
| 商品单位 | 商品编码＋单位编码 | 换算率为当前单位转基础单位；基础单位换算率固定为1 |
| 商品价格 | 商品编码＋价格类型＋客户编码 | 价格类型standard、retail、wholesale、customer；仅customer类型需客户编码 |
| 供应商商品 | 供应商编码＋商品编码 | 供应商货号在同供应商下唯一；采购单位须有现有商品换算 |

商品新增会通过原资料命令自动创建基础单位换算。包装单位换算请随后导入，再显式更新商品默认采购或销售单位。同一文件中新建的分类、父分类或其他引用不会被自动串联创建；将引用资料分批导入并完成后再上传依赖资料。

## 数据与更新规则

编码和条码必须使用Excel的文本单元格；填写前先设为文本，以保留前导零。数字、科学计数、自定义数字显示格式或日期单元格不能还原真实编码，预览会明确拒绝。电话建议也设为文本。不要以公式生成内容后直接上传；请复制并粘贴为值。

数量、价格和换算率最多20位数字、6位小数，数值来自工作簿XML原文并由后端使用精确小数校验。数量和价格不能为负，换算率必须大于零。提前期为0到3650的整数天数。空值和显式0不同；新增可选数值留空采用既有资料默认值，并在完整清洗值中显示。更新时已映射数值列不能留空。

默认“仅新增”不覆盖已有定位键。“仅更新”要求目标已经存在，未映射列保留原值。映射的可清空文本、备注或可选引用列若留空，会按现有资料规则清空，不自动当作“保持原值”。提交前对照原值和完整清洗值；基础单位及原关联关系的不变量仍由现有资料命令检查。

文本两端空白（含全角空格）会去除；商品名、名称、简称、型号、规格中的`*`和`＊`规范为`×`。编码不改大小写，邮件、电话和备注不会被乘号规则替换。系统不会自动合并同名或近似名称资料。

商品属性列写作`属性:模板key`，例如`属性:直径`；必须与所选分类的属性模板一致。必填、枚举选项、数值和布尔规则沿用现有商品编辑；布尔可填是/否、true/false或1/0。分类属性模板变化后，旧预览不会静默采用新定义。

## 预览、执行与重试

上传只生成预览，不修改业务资料。任何预览错误都会阻止整个批次确认；可下载失败行、修正后重新上传。通过预览后，由原创建者确认。后台逐行提交，已完成行保留业务来源；刷新页面可以继续查看持久进度。

网络异常时使用“重试原提交”，保留原文件、选项或命令内容以及原提交键。已确认后台任务可在会话结束后继续，但每一行都会重新检查创建者、组织和当前权限。撤权或账号停用会暂停该批次后续执行；恢复后由创建者重试失败行。

只允许重试可重试的失败行，成功行不能重复执行。目标、引用、分类模板或换算版本变化属于需要重新预览的冲突；系统不会自行刷新版本来覆盖人工修改。普通临时故障重试使用原冻结输入。批次摘要由已持久化行状态汇总，队列或浏览器回执不是业务成功依据。

原工作簿只在请求期间处理，上传临时文件关闭后释放。上传7天后原值、清洗值、引用正文及详细错误会清理，不能再下载或执行到期正文。批次摘要、成功状态、业务目标和既有审计永久保留；清理普通幂等记录不会使成功行重新创建。完整结果文件用于核对；失败行文件保留原列顺序，可修正后重新上传。导出内容均按文本写入，不执行以`=`、`+`、`-`或`@`开头的内容。

## 运行和恢复

正常使用现有Celery worker与beat。导入调度独立于向量与其他Outbox处理，每5秒扫描持久任务，不需要模型服务。

```bash
uv run --project apps/api celery -A forge_erp.workers.celery_app.celery_app worker --loglevel=info
uv run --project apps/api celery -A forge_erp.workers.celery_app.celery_app beat --loglevel=info
```

修复服务故障后，可手动恢复已确认的任务并执行过期正文清理；`--limit`限制每个组织本次执行的行数，默认100。每次命令创建独立数据库连接池并关闭；数据库角色必须为受限`forge_app`。

```bash
uv run --project apps/api python -m forge_erp.workers.catalog_import --limit 100
uv run --project apps/api python -m forge_erp.workers.catalog_import --organization <组织UUID> --limit 100
```

这些恢复命令不会代替用户确认、自动刷新冲突版本、复活到期批次或重做成功行。失败且可重试的行仍需由原创建者在界面确认重试。
