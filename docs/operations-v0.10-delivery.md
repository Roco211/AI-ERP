## 实施摘要

| 工作区 | 已实现的行为 | 业务写入边界 |
|---|---|---|
| `/imports` 资料导入 | 10 种 Catalog 资源的 xlsx 模板、原值与清洗值预览、显式新增/更新、错误下载、逐行进度、失败行重试和业务来源 | 上传只保存预览；确认后每行调用原 Catalog Command，业务、成功状态、目标 ID、Audit/Outbox 在同一事务提交 |
| `/replenishment` 补货 | 组织库存与占用、有效采购待到、30 个完整业务日净销量、提前期及静态补货分支；服务器数量/金额预览与过期依据检查 | 用户复核供应商、仓库、单位和价格后，仅调用原采购保存 Command 创建 DRAFT，不确认采购或增加库存 |
| `/dashboard` 经营概览 | 日期区间净销售、实际成本与毛利、收付款及退款；当前往来、库存估值和补货数量；趋势及来源分页 | 使用既有有效事实，只读聚合，不增加另一套库存、成本或资金事实 |

所有流程沿用现有 Python/FastAPI、PostgreSQL 18、Redis/Celery 和 Next.js 单体架构。HTTP 会话、认证租户上下文、非特权 `forge_app`、RLS、Decimal、权限、request ID 和 Problem Details 保持既有边界。只读结果在认证查询前建立一致数据库快照，相关写入仍使用正常事务。

导入新增依赖用于 xlsx 解析、输出及文件上传；未引入文件云服务、新数据库或消息基础设施。本阶段不实施交易单据批量导入、库存/资金直接导入、自动下单、自动采购确认、AI 业务工具或会计报表。

## 安装、升级与启动

以下命令从仓库根目录执行，使用既有配置和锁文件。已有环境保留 `.env`、数据库卷及业务数据；首次开发配置可先运行 `make env`。升级已有环境前完成备份，并安排数据库索引创建所需的维护时间。

```bash
uv sync --project apps/api --locked
pnpm install --frozen-lockfile
make infra
uv run --project apps/api alembic -c apps/api/alembic.ini upgrade head
uv run --project apps/api alembic -c apps/api/alembic.ini current
```

`current` 应显示 `0015_reporting`。API/worker 使用受限 `forge_app` 连接，迁移使用单独配置的迁移连接；不要交换两类凭据。需要开发管理员及新权限时再执行：

```bash
make seed
```

分别在独立终端启动开发服务：

```bash
make api
make web
make worker
make beat
```

浏览器入口为 `http://localhost:3100`，后端默认 `127.0.0.1:8100`；浏览器业务请求使用同源 `/api`。前端生产构建及本地运行可使用：

```bash
pnpm build
pnpm --filter @forge/web start
```

Next 同源代理的等待上限显式设置为 120 秒。文件仍受 API 的 10,000,000 字节、10,000 数据行和 64 列等限制；提高等待上限没有取消输入边界。额外反向代理若存在，也需核对上传体积和超时设置。同源生产浏览器已实际上传 10,000 行，预览及结果读取约 10.1 秒，验证首尾分页和业务资料零写入；不将开发机单次计时作为生产容量承诺。

## 后台恢复与七天正文清理

常规运行使用既有 Celery worker 和 beat，每 5 秒独立扫描已确认导入任务。导入不依赖 embedding 的成功或其 Outbox 队头；业务成功只由数据库持久行状态证明。

服务恢复后，也可以手动处理已确认的待执行行并清理到期正文：

```bash
uv run --project apps/api python -m forge_erp.workers.catalog_import --limit 100
IMPORT_ORGANIZATION_ID='替换为目标组织UUID'
uv run --project apps/api python -m forge_erp.workers.catalog_import --organization "$IMPORT_ORGANIZATION_ID" --limit 100
```

按组织执行前，将变量值替换为已确认目标的 UUID。`--limit` 为每个组织本次最多执行的业务行数，范围 1–10,000，默认 100；正文清理另有内部有界批量。命令每次建立并关闭独立数据库连接池，核对该连接实际使用 `forge_app` 且没有超级用户、绕过 RLS 或建库/建角色能力。手动命令直接处理数据库任务，不需要 Redis 可用。

这是“恢复待执行行并清理正文”的组合命令，不是仅清理模式。多次执行可继续处理剩余任务，但不会替用户确认新批次、自动重试失败行、更新过期版本或重做成功行。可重试的失败行由原创建者在页面选择；目标或引用版本冲突需重新预览。

原 xlsx 只在请求期间处理，上传临时文件关闭后释放。上传七天后，原值、清洗值、引用正文和详细错误不再允许下载或执行，并由轮询/手动命令清理。成功行的最小状态、业务目标、哈希、来源和既有审计保留，普通幂等缓存到期或删除不使它重新执行。清理跳过正在执行的行事务，后续再处理。

若执行进程在一行提交前终止，该行事务回滚并由后续 worker 恢复；若已提交但回执丢失，恢复时读取永久成功状态。页面刷新从持久批次恢复进度，不能根据浏览器未收到回执判断业务没有发生。

## 限制与需要复核的选择

1. **导入按行提交。** 同一文件可以部分成功，成功行保留。修复失败行不回滚其他已完成资料；不支持文件内自动创建引用依赖、交易单据或库存数量导入。
2. **正文保留七天，最小结果持续保留。** 到期未执行行不能恢复正文继续运行；这是本版运行选择，未定义完整的企业档案和合规保留策略。
3. **确认任务绑定真实创建者。** 已确认任务可跨登录会话执行，但每一行检查组织、账号和当前权限；创建者确认/重试范围及授权撤回语义见 ADR0016。
4. **补货是确定性建议。** 当前组织汇总库存，使用过去 30 个完整业务日、七天复核周期及已配置提前期；缺提前期与显式零天不同。退货不重开采购待到。没有自动推断箱规、最低订货倍数或预测模型。
5. **采购需要显式复核。** 价格缺失不按零处理；手工零价须明确输入。单位不能精确表达建议量时改选基础单位或填写数量与原因。依据、换算或报价变化要求重新复核，最终只创建草稿。
6. **经营概览使用当前有效事实。** 日期区间统计可因后续合法冲销而重算；当前应收应付、估值和补货数量不构成历史余额。它不是会计利润或关账报表，资金未启用、旧来源不完整和成本缺失均需明确显示。
7. **一致快照以单次请求为界。** 卡片、趋势及一次来源分页内部一致；不同请求可能看到新业务事实，不承诺跨请求冻结历史时点。业务时区来自部署配置，默认 `Asia/Shanghai`。
8. **工具链维护。** CI 保留 GitHub Actions 旧 Node 运行时迁移提示；动作在 runner 提供的 Node 24 下已通过。本阶段未升级动作主版本。
9. **运行规模尚需实际部署验证。** 输入有界、预览分块持久化、业务逐行事务；120 秒同源等待及索引降低已识别的风险，但不代表已完成生产容量、长时间运行或高可用验收。
