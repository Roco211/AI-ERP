# 库存 v0.6 验收清单

状态：规划清单，所有功能项尚待实施与验证；不是测试通过报告。

规范：[库存 v0.6 施工规范](inventory-v0.6.md)。新增政策：[ADR 0012](adr/0012-inventory-ledger-and-posting.md)。勾选必须附实际提交、命令、测试用例/报告及结果；历史 v0.5 CI、测试夹具或 skipped 项不能证明本阶段完成。下文“建议规则”须先按 ADR 评审确定；规则变化时同步更新验收预期。

## A. 范围与架构（I0–I1）

- [ ] A01 记录 Catalog 评审/合并基线、库存分支与实际 migration head；保留既有数据与历史。
- [ ] A02 ADR D1–D6 有明确结论，未定细节不伪装为原规范；不提前建设采购、销售、资金、AI 业务工具。
- [ ] A03 冻结技术栈、模块化单体及现有认证/事务基础保持；没有新增禁用基础设施。
- [ ] A04 Domain 不依赖 FastAPI；Router 无业务计算；全部库存写入经过 Command/InventoryEngine；代码边界检查覆盖其他模块直接更新余额。
- [ ] A05 新租户表 ENABLE + FORCE RLS、复合租户外键、唯一约束和必要索引齐备；forge_app 非 owner/superuser/BYPASSRLS。

## B. 账本、单位与成本（I1）

- [ ] B01 每次现有量/占用变化都有不可变事实；forge_app 直接 UPDATE/DELETE/TRUNCATE 流水被拒绝，触发器防改写测试通过。
- [ ] B02 现有量、占用、库存金额及占用明细均能从流水对账；流水 sequence 明确，不依赖时间排序猜测先后；历史业务日期不能回溯改变成本序列。
- [ ] B03 数据库拒绝负现有量、负占用及 reserved > on_hand；API 返回明确领域错误。
- [ ] B04 基本单位统一计算；1 箱=1000 个、输入 2 箱，保存 2000 个及原单位/因子/版本快照。
- [ ] B05 草稿换算变化需重新确认；过账历史不受换算/商品名称变更影响；停用后的原快照仍可查询及合法冲销。
- [ ] B06 float、非有限值、越界、不可表示的小数及负向非法输入被拒绝；API 数值输出为字符串。
- [ ] B07 入库 100@10，再入库 100@12 → 数量 200、金额 2200、均价 11；出库 50 → 成本 550、余额数量 150、金额 1650、均价仍 11。
- [ ] B08 全量出库库存金额精确归零；尾差有据可查；再次入库均价正确，不沿用空库存历史成本。
- [ ] B09 零成本、微量数量、六位成本舍入、部分出库金额边界与 NUMERIC 上限有明确预期及自动测试，无负金额或隐式改值。
- [ ] B10 Hypothesis 生成合法操作序列，每步校验数量/占用/金额/重放结果一致及不变量；不是仅重复几组固定样例。

## C. 占用、并发与事务（I1–I3）

- [ ] C01 现有 100，占用 60 → 现有仍 100、占用 60、可用 40；金额及均价不变。
- [ ] C02 消费上述占用出库 20 → 现有 80、占用 40、可用 40；再释放 10 → 占用 30、可用 50。
- [ ] C03 超额占用/释放/消费、使用别的来源占用均拒绝；无占用出库不得动用已占用数量；没有通用手工占用 API。
- [ ] C04 现有 10，并发出库两次各 7，只有一次成功；失败事务不留流水、余额变更或成功幂等响应。
- [ ] C05 同一库存键首次创建余额/首次入库并发安全，唯一一条余额且流水无丢失。
- [ ] C06 多商品双向调拨遵循同一锁序，验证无丢失更新和预期内的锁等待/重试；不同库存键不被组织总锁串行化。
- [ ] C07 过账与主数据停用/换算变更的交叉并发有明确结果，无失效引用新过账；首次入库和停用不能同时错误成功。
- [ ] C08 故障分别注入流水写后、余额更新后、单据更新后、Audit/Outbox/幂等保存时，整笔事务回滚且可安全重试。
- [ ] C09 同 key 同请求重放原回执；同 key 不同请求返回 IDEMPOTENCY_KEY_REUSED；不同单据操作不串响应。
- [ ] C10 不同 key 同时过账同单、幂等记录过期后重复过账，都不会重复扣增库存；数据库唯一约束与状态检查生效。
- [ ] C11 请求权限撤销后不能借幂等重放执行操作或读旧成本；超时后的原 key 重试不重复过账。

## D. 单据操作（I2–I4）

- [ ] D01 保存/编辑草稿不改变库存；expected_version 过期拒绝；单据不接受 generic status PATCH。
- [ ] D02 期初按基本单位成本入账，不能覆盖已有有效业务；并发期初最多一个成功；零成本必须显式确认。
- [ ] D03 调整原因必填；增加按确认成本入账，减少按当前成本并保护占用；不支持直接覆盖余额或伪造应付。
- [ ] D04 POSTED 内容和行不能经 API/直接 SQL 修改删除，也不能追加行；只有合法冲销更新限定状态元数据。
- [ ] D05 无后续依赖的整单冲销产生关联反向流水，恢复操作前数量/金额/均价，原事实不变；重复冲销拒绝。
- [ ] D06 原单有后续流水时按已评审政策拒绝，包括后续单据已冲销的情形；双仓任何一端有依赖时调拨整单不能部分冲销。
- [ ] D07 调拨源仓减少与目标仓增加的数量、金额相抵；目标均价正确；跨租户/同仓调拨拒绝。
- [ ] D08 调拨任一行或任一仓失败整单回滚；占用不随调拨迁移。
- [ ] D09 盘点未填写数量不等于零，未选商品不被影响；有基准、实盘、差异、原因和成本确认记录。
- [ ] D10 盘点期间入出库/占用引起基准变化，过账整单拒绝 STOCKTAKE_STALE；刷新不静默覆盖实盘数据，需重新确认。
- [ ] D11 盘盈明确成本，盘亏遵守当前成本，实盘少于已占用量不能自动释放占用或过账。
- [ ] D12 全零差异盘点可过账并留审计，不伪造数量流水；混合差异只对真实变化写流水。

## E. 安全、可观测性与后台（所有增量）

- [ ] E01 使用真实 PostgreSQL 18 的 forge_app 测试跨租户 SELECT/INSERT/UPDATE、关联外键、无租户上下文及连接池租户切换，均无数据泄漏。
- [ ] E02 API 拒绝客户端 organization_id，跨租户 ID 返回不泄露存在性的错误；worker/维护命令显式设置租户。
- [ ] E03 数量只读、成本读取、各业务动作、冲销、对账的权限分别测试；仅隐藏按钮不算通过。
- [ ] E04 无 product.cost.read 时，详情、列表、流水、错误、Audit 可读入口及幂等回执均不泄露成本；日志/Outbox 仅包含必要元数据。
- [ ] E05 关键变更 Audit 记录 actor/source/资源/前后变化/request ID；Outbox 与业务同事务，库存事件处理器可重试且去重。
- [ ] E06 Redis/worker 暂停时业务过账仍原子提交；恢复后 Outbox 继续处理，重复消费不重复改变库存。
- [ ] E07 Cookie/Origin、Problem Details、request ID、structured logging 与登录/退出回归通过；不记录凭据或完整敏感请求。

## F. 工作台与用户流程（I2–I5）

- [ ] F01 库存页面按商品/仓库显示现有量、占用、可用量；成本按权限呈现；余额可追溯到流水及来源单据。
- [ ] F02 键盘 ProductPicker 可选商品/单位/数量并进入单据；数量和正式金额由服务端验证，没有 float 权威计算。
- [ ] F03 表单覆盖输入错误、保存、版本冲突、过账确认、重复点击、网络结果不明及原 key 重试；POSTED 页面只读。
- [ ] F04 Playwright 实际完成期初→查看余额/流水→合法冲销，以及调整、调拨、盘点成功/冲突场景；包含无成本权限和移动端核心路径。
- [ ] F05 Vitest 验证关键表单/状态交互；真实浏览器与真实 API/数据库流程不能全由 mock 替代。
- [ ] F06 低库存按已评审商品级口径，覆盖跨仓汇总、无余额、零阈值、占用影响；不虚构采购建议或销量。
- [ ] F07 分页/筛选/稳定排序及页数上限正确，流水并发新增时翻页不重复漏读；超出单据行数上限明确拒绝。
- [ ] F08 记录代表性测试数据规模、查询计划、数据库/API/整页耗时和设备条件；发现全表无界加载则修复，不把少量样例测试称为生产容量保证。

## G. 对账、迁移、CI 与交付（I5）

- [ ] G01 一致快照对账报告包含水位及差异；在独立测试数据库损坏余额/占用投影后能发现，dry-run 不修改数据。
- [ ] G02 经授权维护重建可恢复数量、金额、平均成本和占用明细；范围外租户/库存键不变；原流水不变，修复留审计。
- [ ] G03 重建与普通写入互斥或同锁协调；无权限、范围缺失、维护条件不满足时拒绝实修复。
- [ ] G04 空库、Bootstrap 0001、带数据 Catalog 0004、库存前一增量均可升级到实际 head；原资料/权限/流水保留，merged migrations 未改写。
- [ ] G05 uv.lock、pnpm-lock.yaml 通过冻结安装；Ruff、format check、Pyright、pytest 全过，库存相关测试无跳过冒充通过。
- [ ] G06 pnpm lint、typecheck、Vitest、production build、Playwright 全过，Bootstrap/Catalog/本地搜索回归无退化。
- [ ] G07 OpenAPI→TypeScript 可重复生成且无 drift；没有手工编辑生成文件。
- [ ] G08 GitHub Actions 纳入 inventory/** 分支并保留 PR 检查，实际交付提交的 CI 全绿，报告附 commit/run 链接。
- [ ] G09 可选库存开发 seed 幂等、通过业务 Command、不覆盖用户已改资料、不含生产秘密；运行和维护说明与真实命令一致。
- [ ] G10 完整交付报告包含 implementation summary、final repository tree、run commands、migration status、test results、unresolved issues、architecture decisions requiring review；全部满足后才建议 inventory-v0.6 标签。
