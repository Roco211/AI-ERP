# 轻量资金 v0.9 验收清单

状态：后端 20/27 项已验证；页面生产验收与最终提交 CI 进行中。未通过项目继续保留待验收。

## A. 来源与切换

- [x] A01 空库和带销售/采购事实的 v0.8 数据库可升级，旧数据与标签不被重写。
- [x] A02 资金启用切点明确，旧单不自动作为未收付款；期初记录可追溯、防重复。
- [x] A03 销售出库形成应收，采购入库形成应付，金额来自冻结商业事实。
- [x] A04 订单确认/关闭不生成现金，不混合业务、履约和结算状态。
- [x] A05 分批过账及精度尾差按来源行/单据的已冻结金额汇总。
- [x] A06 启用前单据后续退货/冲销有明确、可测试的资金处理路径。

## B. 收付与纠正

- [x] B01 应收/应付来源、客户/供应商往来和收付款明细可查询并追溯。
- [x] B02 部分核销、全额核销、一次多来源核销金额准确。
- [x] B03 超额、重复来源、跨对象、错方向、非法精度和零/负收付金额拒绝。
- [x] B04 未付款退货冲减欠款；已付款退货显示待退款；部分退款和全额退款正确。
- [x] B05 采购退货商业冲减与库存价值分离，不能用当前成本计算退款。
- [x] B06 收付款/退款冲销保留历史，并校验依赖及额度；原业务冲销与资金原子协调。
- [x] B07 期初欠款/退款余额、重复录入重试、错误纠正可核对。
- [x] B08 不同状态、退货/退款/冲销组合后余额可从来源及有效资金事实对账。

## C. 安全和并发

- [x] C01 所有新租户表 FORCE RLS，forge_app 下跨租户 SQL/API 读写和引用被拒绝。
- [x] C02 资金读取/收付/退款/冲销/启用权限独立，仓管过账不泄露资金。
- [x] C03 同键重试只产生一次事实，不同 body 复用键拒绝，撤权后旧键拒绝。
- [x] C04 两次收付竞争同余额、退款/退货/冲销竞争均不会超额或丢失。
- [x] C05 业务、资金、Audit、Outbox、幂等及 COMMIT 故障均整笔回滚。
- [x] C06 已过账资金事实不可更新删除；余额和额度由服务端验证。
